the matchup

Same two commands, two sessions apart. One remembers the assignment; one doesn't.

Stock codex execLOST
$ codex exec "migrate billing to new schema"
… session ends, summarized …

$ codex exec resume --last "continue"
> continuing. what's the task again?
  (transcript survived. the point of it didn't.)

Resume brings back messages, not the objective that framed them.

codex‑goal runWON
$ codex_goal.py set "migrate billing to new schema"
$ codex_goal.py run
> [codex-goal] persisted objective: migrate billing…

… session ends …

$ codex_goal.py run --last
> [codex-goal] persisted objective: migrate billing…
  (re-injected before Codex sees anything else.)

Every new or resumed run gets the same goal text, re-stated, every time.

how it scores

  • 01 Goal state lives under ~/.codex-goal — outside the directory Codex's own sandbox lets it write to. set is a human command; the wrapper never calls it on Codex's behalf.
  • 02 Every set is versioned: the previous goal moves to a capped history instead of being silently overwritten.
  • 03 Writes are atomic (temp file + rename) under an exclusive file lock — a crash mid-write can't leave torn JSON.
  • 04 run never edits the goal. It only appends one line to a separate run-log, after the child exits, with the real exit code.
  • 05 Codex is spawned via an argv list, never a shell string — a goal containing ; rm -rf / # is one opaque argument, not a command.
  • 06 Ctrl‑C / SIGTERM sent to the wrapper is forwarded to the Codex child, so cancellation behaves exactly like calling codex directly. The wrapper's exit code is the child's.

rules of the game

  • 1 goal One objective per project at a time. Not a task list, not a scheduler, not a replacement for your issue tracker.
  • no force The injected text is plain, visible user context — it carries no special authority inside Codex. A model can still choose to ignore it, same as any other instruction.
  • no grading This only guarantees the goal is faithfully re-stated every run. It does not inspect diffs or grade progress — pair it with finishline-supervisor for that.
  • plain json $CODEX_GOAL_HOME is ordinary local storage with your file permissions, no encryption. Don't put secrets in goal text.
  • local lock Locking is advisory and local-filesystem only — it doesn't coordinate over NFS/SMB or across machines.
  • your flags run forwards whatever codex exec flags you give it, including dangerous ones if you ask for them. This wrapper adds or removes none of Codex's own safety behavior.
